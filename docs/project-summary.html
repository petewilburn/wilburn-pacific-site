Portfolio Builder Project Summary

Portfolio Builder is a portfolio and lead-generation website for Wilburn Pacific, currently operating as a static React site on Azure Static Web Apps with a single Azure Function handling contact submissions.

Overview

The project presents Wilburn Pacific's industrial engineering services in a modern marketing site format while also supporting structured inquiry handling. It includes public-facing pages for services, projects, careers, company information, and contact.

The repository still contains an older Express, Drizzle, and PostgreSQL implementation path, but that stack has now been quarantined under legacy/ because it does not appear to power the current deployment. Most page content now lives directly in the frontend, while the contact flow is handled through the serverless api/contact function.

Goals

  • Present Wilburn Pacific's capabilities and project work in a polished portfolio format.
  • Capture new business inquiries through a contact workflow.
  • Support a clean Azure Static Web Apps deployment path with serverless contact handling.
  • Support cloud deployment patterns compatible with Azure Static Web Apps and Azure Functions.

Architecture

Frontend

The frontend lives under client/src and uses React, TypeScript, and Vite. Client-side routing is handled with Wouter, and the UI is built with Tailwind CSS plus a shadcn/ui component setup on top of Radix UI primitives.

  • Renders the core marketing pages and navigation shell.
  • Displays services and projects from static in-file content.
  • Uses Framer Motion for visual transitions and section animation.
  • Submits contact requests from the contact page.

Deployed Backend Surface

The only clearly active backend surface in the deployed app is the Azure Function under api/contact.

  • Accepts contact payloads.
  • Routes emergency requests differently from standard inquiries.
  • Sends email using Azure Communication Services Email.

Legacy Or Local-Only Backend Path

The repository still contains an Express 5 backend under legacy/server, plus archived Drizzle and PostgreSQL configuration under legacy/. That path has been quarantined from the active app surface and is not part of the current Azure Static Web Apps deployment model.

Shared Code

Shared modules under shared now focus on active frontend-safe types, while the older Express-backed API contract and database schema are preserved under legacy/shared.

Database And ORM Status

PostgreSQL and Drizzle ORM are still preserved in the repository archive, but they do not appear to back the current deployed UI. The archived schema still includes services, projects, and inquiries.

Deployment Model

The current deployment path uses Vite to build static frontend assets and Azure Static Web Apps to deploy those assets alongside the api folder as Azure Functions. The Express backend is not part of that deployment flow.

Notable Implementation Details

  • The frontend uses an industrial visual direction with animation and custom sections rather than a default starter layout.
  • Services and project content are currently embedded directly in the frontend pages rather than loaded from a live backend.
  • The contact workflow is serverless and routes through Azure Functions.
  • The former Express, Drizzle, and PostgreSQL stack has been quarantined under legacy/ rather than deleted outright.
  • Static Web App routing support is already configured.

Current State Versus Legacy Components

Clearly active today: static frontend pages, Azure Function contact handling at /api/contact, the Azure Static Web Apps deployment workflow, and frontend-safe shared types under shared/types.ts. Archived legacy code now lives under legacy/, including the old Express server, Drizzle and PostgreSQL configuration, older shared route contracts, and the unused React Query hooks.

Environment and Configuration

  • ACS_CONNECTION_STRING for Azure Communication Services Email.
  • SENDER_ADDRESS for outbound email sending.

Legacy or optional local-only requirements still preserved in the repository archive include DATABASE_URL for PostgreSQL connectivity and PORT for the archived Express server, defaulting to 5000.

How the App Runs Today

  • npm run build builds the Vite frontend.
  • Azure Static Web Apps deploys the built frontend and the api folder.
  • npm run dev now starts the Vite frontend development server.
  • npm run check runs the TypeScript compiler.

The archived backend code remains under legacy/, but it is no longer part of the default root scripts.

Summary

This project is currently best described as a static marketing and inquiry platform built around a React frontend and a serverless Azure contact function. The older Express, Drizzle, and PostgreSQL backend path has now been quarantined under legacy/, preserving the prior implementation without keeping it wired into the active codebase.
